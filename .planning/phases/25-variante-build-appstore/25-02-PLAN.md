# 25-02 — Target y esquema `ExtractorApp AppStore` + empaquetado

## Objetivo

Añadir al proyecto un segundo target que compile la variante App Store desde
el mismo código, con su propio esquema, y un script que la archive, exporte y
empaquete para App Store Connect. El target `ExtractorApp`, su esquema y
`release-macos.sh` no cambian (MASBUILD-01).

## Tareas

### T1 — Target nuevo en `project.pbxproj`

Duplicar a mano la estructura del target `ExtractorApp` con IDs nuevos y
únicos:

- `PBXNativeTarget` «ExtractorApp AppStore», con producto `ExtractorApp.app`
  propio en `Products` y fases:
  - Sources, Frameworks (vacía), CopyFiles (`core.py`, `extractor_url.py` →
    `scripts`) y Resources.
  - «Bundle Python Runtime» con
    `export EXTRACTOR_VARIANT=appstore` antes de llamar a `bundle-python.sh`.
  - Sin fase de Chromium y sin Sparkle.
- Sincronización de ficheros:
  - El grupo sincronizado `ExtractorApp/` se añade también a este target.
  - Nueva `PBXFileSystemSynchronizedBuildFileExceptionSet` para él, que
    excluye `Info.plist`, `AppStore-Info.plist`, `ExtractorApp.entitlements`,
    `ExtractorApp-AppStore.entitlements`, `Models/Services/RuntimeUpdater.swift`
    y `Views/CheckForUpdatesView.swift`.
  - La excepción del target actual pasa a excluir también
    `AppStore-Info.plist`, `ExtractorApp-AppStore.entitlements` y
    `PrivacyInfo.xcprivacy`.
- Configuraciones Debug/Release: copia de las del target actual cambiando
  - `PRODUCT_BUNDLE_IDENTIFIER = com.edefrutos.ExtractorApp.appstore`
  - `PRODUCT_NAME = ExtractorApp`
  - `CODE_SIGN_ENTITLEMENTS = ExtractorApp/ExtractorApp-AppStore.entitlements`
  - `ENABLE_APP_SANDBOX = YES`
  - `INFOPLIST_FILE = ExtractorApp/AppStore-Info.plist`
  - `INFOPLIST_KEY_CFBundleDisplayName = "Extractor URL"`
  - `INFOPLIST_KEY_LSApplicationCategoryType = public.app-category.productivity`
  - `INFOPLIST_KEY_ITSAppUsesNonExemptEncryption = NO`
  - `SWIFT_ACTIVE_COMPILATION_CONDITIONS = "APPSTORE $(inherited)"` (Debug:
    `"DEBUG APPSTORE $(inherited)"`)
  - Mismos `ARCHS`, `MACOSX_DEPLOYMENT_TARGET`, `MARKETING_VERSION` y
    `CURRENT_PROJECT_VERSION`.
- Añadir el target a `targets` del proyecto y a `TargetAttributes`, si existe.

**Verificación (sandbox):**
- El fichero se parsea con un parser de plist ASCII (por ejemplo, el paquete
  `pbxproj` de pip).
- Todos los IDs referenciados existen y no hay duplicados.
- El target `ExtractorApp` conserva idénticos sus fases, enlaces y ajustes,
  salvo las tres excepciones nuevas.

### T2 — Esquema compartido `ExtractorApp AppStore.xcscheme`

Copia del esquema actual que construye, ejecuta y archiva el target nuevo.
Sin acción de test: los tests siguen en el esquema `ExtractorApp`.

### T3 — `scripts/package-appstore.sh`

Sustituye a `spike-appstore.sh` (que se borra):

1. `xcodebuild archive -scheme "ExtractorApp AppStore"`.
2. `-exportArchive` con `method = app-store-connect` y `destination = export`
   (sin subir).
3. Re-firmar el runtime Python: `.so`/`.dylib` sin entitlements y
   `python3.13` con `python-child.entitlements`, con `APPSTORE_IDENTITY`.
   Después, volver a sellar el `.app` con los entitlements de la app (sacados
   del propio `.app` exportado con `codesign -d --entitlements`).
4. `xattr -cr` y comprobaciones:
   - firma válida;
   - sin Sparkle, sin `_tkinter`/Tcl, sin Playwright;
   - sin cuarentena.
5. `productbuild` firmado con `INSTALLER_IDENTITY` →
   `.build-cache/appstore/ExtractorURL-<versión>-<build>.pkg`.

La subida con Transporter sigue siendo manual. Automatizarla es de la
Fase 28.

**Verificación:** `bash -n` y `shellcheck`.
