<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `scripts/release-macos.sh` (canal opcional) → `appcast.xml` publicado | Mismo autor/máquina que ya publica releases estables — sin nuevo actor de confianza |
| Toggle de opt-in (`SettingsView`) → `SPUUpdaterDelegate` | Decisión local del propio usuario de la app, reversible en cualquier momento |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-01 | Tampering | Reutilizar `MARKETING_VERSION` entre un release beta y el estable posterior | accept | Documentado en `RELEASING.md` (Pitfall 1 del research) — el preflight existente (`gh release view`) ya falla explícito ante un tag duplicado; no se fuerza en código porque el usuario controla su propio versionado. |
| T-16-02 | Information Disclosure | Un release "beta" es públicamente visible en GitHub Releases igual que uno estable | accept | Mismo modelo que ya existe hoy (repo público, releases públicos) — `--prerelease` solo añade una etiqueta visual en GitHub, no oculta el asset; aceptable para el alcance de este proyecto (herramienta personal). |
</threat_model>
