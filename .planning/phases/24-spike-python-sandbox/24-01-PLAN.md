# 24-01 — Spike: Python embebido bajo App Sandbox

## Objetivo

Responder con evidencia, antes de invertir en las fases 25–28, a una sola
pregunta: **¿puede la app ejecutar su Python embebido dentro de App Sandbox
y acepta App Store Connect el paquete?**

## Enfoque

Sin tocar el proyecto de Xcode (eso es la Fase 25). `scripts/spike-appstore.sh`
transforma una copia del `.app` Developer ID ya compilado (v2.3):

1. Quita Playwright/Chromium (+ `greenlet`/`pyee`), `_tkinter` + Tcl/Tk
   (`tcl9*`, `tk9.0`, `itcl*`, `thread*`, `libtcl9*.dylib`) y los ejecutables
   auxiliares de Sparkle (`XPCServices`, `Autoupdate`, `Updater.app`). El
   framework de Sparkle se queda porque la app lo enlaza hasta la Fase 25.
2. Bundle ID `com.edefrutos.ExtractorApp.appstore`, nombre visible «Extractor
   URL», `LSApplicationCategoryType` y `ITSAppUsesNonExemptEncryption = NO`.
3. Firma de dentro a fuera: librerías sin entitlements; `python3.13` con
   **solo** `app-sandbox` + `inherit` (`scripts/appstore/python-child.entitlements`);
   el `.app` con sandbox + red cliente + ficheros elegidos por el usuario
   (`scripts/appstore/app.entitlements`).
4. Modo `package`: perfil Mac App Store embebido, entitlements de
   `application-identifier`/`team-identifier` y `.pkg` firmado para Transporter.

Decisiones del usuario (2026-10-20): bundle ID propio
`com.edefrutos.ExtractorApp.appstore`; nombre en la tienda «Extractor URL».

## Verificado en el sandbox Linux (sin firma)

- Sobre una copia del `.app` real de v2.3: 888 MB → **183 MB** tras quitar
  Chromium, Tcl/Tk y los auxiliares de Sparkle.
- Queda **un único ejecutable** Mach-O en `Resources` (`python/bin/python3.13`)
  y 12 librerías (11 `.so` + `libpython3.13.dylib`): el resto de la stdlib
  está enlazado estáticamente en python-build-standalone.
- Ningún fichero contiene símbolos `Tcl_CreateInterp`/`_TclBN_`/`Tk_Init`
  (la causa del rechazo documentado en el foro de Apple 758567).
- `bash -n` + `shellcheck` sin avisos.

## Pendiente (Mac real) — ver `CHECKPOINT-HUMANO.md`

- **Parte A (SBX-01, SBX-03):** ejecutar la variante local con sandbox y
  extraer una URL estática; confirmar que `ExtractorApp` y `python3.13`
  aparecen con sandbox en Monitor de Actividad; recoger violaciones de sandbox.
- **Parte B (SBX-02, SBX-04):** App ID, certificados, perfil, ficha en App
  Store Connect, `.pkg` y entrega con Transporter **sin enviar a revisión**.
  SBX-02 (ubicación del código nativo de Python) se da por resuelto si App
  Store Connect acepta `Contents/Resources/python`; si lo rechaza, el error
  dice qué mover y se mueve en la Fase 25.

## Criterio de salida

- **Éxito:** la extracción funciona con sandbox y Transporter entrega el
  paquete sin errores → fases 25–28 siguen como están.
- **Fallo:** se documenta el error exacto y se replantea el diseño antes de la Fase 25.
