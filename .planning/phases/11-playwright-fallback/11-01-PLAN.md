<objective>
Extender `core.py` para que la extracción de contenido no falle silenciosamente en páginas cuyo contenido real depende de JavaScript del lado del cliente (SPAs). Se añade una heurística de "contenido estático insuficiente" y, si se activa, un fallback automático a Playwright (Chromium headless) que renderiza la página antes de que `_fetch_raw()` devuelva el resultado. Si Playwright no está instalado (paquete pip ausente o `playwright install chromium` nunca ejecutado), la función degrada al HTML estático sin lanzar una excepción no controlada.

Purpose: Cubrir el mayor hueco funcional actual del motor Python (SPAs) sin flag manual, sin cambios en la app SwiftUI y sin romper el comportamiento existente en sitios estáticos.
Output: `core.py` con 2 funciones nuevas + 3 líneas de integración en `_fetch_raw()`, `requirements.txt` actualizado, fixture SPA nueva, y una suite de tests que cubre las 4 ramas de JS-01..04 sin depender de un browser real.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL de usuario → `page.goto()` (Playwright) | La misma URL que ya se pasa a `requests.get()` se pasa también a Chromium headless para renderizarla |
| Contenido renderizado por Chromium → pipeline de extracción | El HTML devuelto por `page.content()` se trata exactamente igual que el HTML de `requests` — mismas funciones de limpieza/parseo downstream, sin lógica de confianza diferenciada |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Denial of Service | `page.goto(wait_until="networkidle")` en páginas con polling/websockets | mitigate | Timeout explícito en milisegundos (`timeout * 1000`) garantiza que como mucho se tarda `timeout` segundos extra por URL — nunca cuelga indefinidamente. Documentado como Pitfall 3 en el research; aceptado como trade-off de v4.0. |
| T-11-02 | Information Disclosure | Chromium headless ejecuta JavaScript arbitrario de la página objetivo | accept | Mismo modelo de confianza que abrir la URL en cualquier browser real — no hay superficie nueva de credenciales/secretos del proyecto expuesta a la página renderizada. Sin sandboxing adicional necesario más allá del propio proceso aislado de Chromium. |
| T-11-03 | Tampering | `pip install playwright` como nueva dependencia externa | mitigate | Paquete oficial mantenido por Microsoft (mismo equipo que el proyecto Playwright), sin alternativas de nombre similar ni señales de typosquatting — ver "Package Legitimacy Audit" en el research. Sin pin de versión exacta en este plan; verificar en el momento de instalar. |
| T-11-SC | Tampering | npm/pip/cargo installs | accept | Este plan añade `playwright` (pip) — paquete de legitimidad verificada (ver arriba), sin script de instalación custom ni post-install hooks sospechosos más allá del propio `playwright install chromium` documentado oficialmente. |
</threat_model>
