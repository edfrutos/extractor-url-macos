# [08-02] Phase 08: Bundle Python Runtime — Plan 02: Integración Xcode

**Wave**: 1 | **Depends on**: None
**Requirements**: BUNDLE-01, BUNDLE-02, BUNDLE-03
**Goal**: Integrar el bundle Python en el proyecto Xcode añadiendo `extractor_url.py` y `core.py` a la fase "Copy Bundle Resources", creando la Run Script Build Phase "Bundle Python Runtime" que invoca `scripts/bundle-python.sh`, y actualizando `PythonBridge.swift` con los métodos `bundledPythonPath()` y `bundledVendoredLibPath()` que resuelven rutas desde `Bundle.main.resourcePath`.

---

## Context

El proyecto Xcode actualmente no incluye los scripts Python ni el runtime en el bundle. `PythonBridge.swift` lee las rutas desde `@AppStorage("pythonPath")` y `@AppStorage("scriptPath")`, asumiendo que el usuario configura manualmente sus rutas locales. Esta fase prepara la infraestructura de bundle que la Fase 9 (Bridge Auto-detección) usará para eliminar esa dependencia de configuración manual.

**Lo que hace este plan:**

1. Los scripts `extractor_url.py` y `core.py` deben estar en `Contents/Resources/scripts/`. Xcode los copia automáticamente si se añaden a la build phase "Copy Bundle Resources".

2. La Run Script Build Phase "Bundle Python Runtime" invoca `${PROJECT_DIR}/scripts/bundle-python.sh` después de "Copy Bundle Resources" y antes de que Xcode firme el `.app`. El script descarga Python, lo merge, instala deps y firma los binarios internos.

3. `PythonBridge.swift` necesita dos métodos estáticos nuevos (`bundledPythonPath()` y `bundledVendoredLibPath()`) que la Fase 9 usará para la auto-detección. En esta fase se añaden los métodos pero la lógica de `run()` sigue usando `@AppStorage` — la Fase 9 conectará todo.

**Estructura de directorios en el bundle resultante:**

```
ExtractorApp.app/
└── Contents/
    └── Resources/
        ├── python/
        │   ├── bin/
        │   │   └── python3.13        ← universal binary (arm64+x86_64)
        │   └── lib/
        │       ├── python3.13/       ← stdlib
        │       └── python-packages/  ← deps vendorizadas
        └── scripts/
            ├── extractor_url.py      ← copiado por Copy Bundle Resources
            └── core.py               ← copiado por Copy Bundle Resources
```

**Ruta del .xcodeproj:** `ExtractorApp/ExtractorApp/ExtractorApp.xcodeproj`
**Grupo principal en Xcode:** `ExtractorApp` (el target principal)
**Ruta de los scripts Python en el repo:** `extractor_url.py` y `core.py` están en la raíz del repositorio (`/Volumes/ESSAGER/__01.-Proyectos/__Herramientas_Desktop/extractor-url/`).

## Tasks

### Task 1: Añadir scripts Python a "Copy Bundle Resources" en Xcode

**File**: `ExtractorApp/ExtractorApp/ExtractorApp.xcodeproj/project.pbxproj`
**Action**: Edit (via Xcode UI — ver instrucciones)

Los scripts `extractor_url.py` y `core.py` están en la raíz del repositorio. Deben añadirse al target de la app de forma que Xcode los copie a `Contents/Resources/scripts/` durante el build.

**Procedimiento en Xcode:**

1. En el Project Navigator (panel izquierdo), hacer clic derecho sobre el grupo `ExtractorApp` (el grupo de la app, no el proyecto raíz).
2. Seleccionar "Add Files to ExtractorApp...".
3. Navegar a la raíz del repositorio y seleccionar `extractor_url.py`.
4. En el diálogo, asegurarse de:
   - "Copy items if needed": **desactivado** (queremos referencia al archivo original, no copia)
   - "Added to targets": **ExtractorApp** activado
   - "Create groups": seleccionado
5. Repetir para `core.py`.
6. Seleccionar el target `ExtractorApp` → pestaña "Build Phases" → sección "Copy Bundle Resources".
7. Verificar que `extractor_url.py` y `core.py` aparecen en la lista.
8. Con ambos archivos seleccionados en "Copy Bundle Resources", hacer clic en el campo "Destination" (abajo de la lista) si aparece la opción, y añadir la subcarpeta de destino `scripts` en el campo "Subpath". Si Xcode no muestra "Subpath" directamente en la UI, ver alternativa abajo.

**Alternativa si Xcode no permite Subpath en la UI:** Editar `project.pbxproj` directamente para añadir la entrada `dstSubfolderSpec` y `dstPath = "scripts"`. Buscar la sección `PBXCopyFilesBuildPhase` o la entrada correspondiente de los archivos `.py` en `PBXResourcesBuildPhase` y añadir:

```
/* Si ya están en Copy Bundle Resources pero sin subcarpeta, crear una
   nueva build phase de tipo "Copy Files" separada: */
/* En Xcode: Build Phases → "+" → "New Copy Files Phase" */
/* Destination: "Resources", Subpath: "scripts" */
/* Añadir extractor_url.py y core.py a esta nueva fase */
/* Eliminar los archivos de "Copy Bundle Resources" original si quedaron ahí */
```

**Método recomendado — New Copy Files Phase:**

1. En Build Phases, clic en "+" → "New Copy Files Phase".
2. Renombrar la fase a "Copy Python Scripts".
3. Destination: `Resources`
4. Subpath: `scripts`
5. Clic en "+" dentro de la fase y añadir `extractor_url.py` y `core.py`.
6. Si los archivos ya están en "Copy Bundle Resources" sin subcarpeta, eliminarlos de ahí para evitar duplicados.

**Verificación inmediata:** Hacer un build de prueba (Cmd+B). En el build log, buscar:
```
Copy extractor_url.py → .../Contents/Resources/scripts/extractor_url.py
Copy core.py → .../Contents/Resources/scripts/core.py
```

### Task 2: Crear Run Script Build Phase "Bundle Python Runtime"

**File**: `ExtractorApp/ExtractorApp/ExtractorApp.xcodeproj/project.pbxproj`
**Action**: Edit (via Xcode UI)

Añadir una Run Script Build Phase que invoque `bundle-python.sh`. Esta fase debe ejecutarse **después** de "Copy Python Scripts" (o "Copy Bundle Resources") y **antes** de que Xcode firme el `.app`.

**Procedimiento en Xcode:**

1. Seleccionar el target `ExtractorApp` → pestaña "Build Phases".
2. Clic en "+" → "New Run Script Phase".
3. Renombrar la fase a "Bundle Python Runtime".
4. En el campo "Shell": `/bin/bash`
5. En el campo del script (el área grande):
   ```bash
   set -euo pipefail
   "${PROJECT_DIR}/scripts/bundle-python.sh"
   ```
6. Activar "Show environment variables in build log" (checkbox) — útil para debugging.
7. Dejar "Based on dependency analysis" **desactivado** para que siempre se ejecute.
8. Arrastrar la fase "Bundle Python Runtime" en la lista de Build Phases para que quede **después** de "Copy Python Scripts" (o "Copy Bundle Resources") y **antes** de cualquier fase de signing.

**Orden correcto de Build Phases:**
```
1. Dependencies
2. Compile Sources
3. Link Binary With Libraries
4. Copy Bundle Resources     ← copia Info.plist, assets, etc.
5. Copy Python Scripts       ← copia extractor_url.py, core.py → Resources/scripts/
6. Bundle Python Runtime     ← descarga Python, merge, pip, codesign binarios Python
7. [Xcode automático] Sign and Entitle ExtractorApp
```

**Input/Output files (opcional pero recomendado para invalidación de cache):**

En "Input Files":
```
$(PROJECT_DIR)/scripts/bundle-python.sh
```

En "Output Files":
```
$(BUILT_PRODUCTS_DIR)/$(CONTENTS_FOLDER_PATH)/Resources/python/bin/python3.13
```

Con Output Files configurado, Xcode omite la fase si el output ya existe y el input no cambió, acelerando builds incrementales.

### Task 3: Añadir `bundledPythonPath()` y `bundledVendoredLibPath()` a PythonBridge.swift

**File**: `ExtractorApp/ExtractorApp/ExtractorApp/Services/PythonBridge.swift`
**Action**: Edit

Añadir una extensión `PythonBridge` con los métodos estáticos que resuelven rutas desde `Bundle.main.resourcePath`. Estos métodos los usará la Fase 9 para la auto-detección de rutas; en esta fase solo se declaran.

Añadir al final de `PythonBridge.swift`, después del cierre de la clase `PythonBridge` y antes de `// MARK: - IOCollector`:

```swift
// MARK: - Bundle Paths (Fase 8: rutas del intérprete embebido)

extension PythonBridge {

    /// Ruta al intérprete Python universal embebido en el bundle.
    /// Devuelve nil si el binario no existe o no es ejecutable
    /// (p.ej. en un build de desarrollo antes de ejecutar bundle-python.sh).
    static func bundledPythonPath() -> String? {
        guard let resourcePath = Bundle.main.resourcePath else { return nil }
        let path = resourcePath + "/python/bin/python3.13"
        guard FileManager.default.isExecutableFile(atPath: path) else { return nil }
        return path
    }

    /// Ruta al script principal extractor_url.py en el bundle.
    /// Devuelve nil si el archivo no existe.
    static func bundledScriptPath() -> String? {
        guard let resourcePath = Bundle.main.resourcePath else { return nil }
        let path = resourcePath + "/scripts/extractor_url.py"
        guard FileManager.default.fileExists(atPath: path) else { return nil }
        return path
    }

    /// Ruta a las deps Python vendorizadas (python-packages/).
    /// Siempre devuelve la ruta construida; no valida existencia
    /// porque el directorio se crea en build time.
    static func bundledVendoredLibPath() -> String? {
        guard let resourcePath = Bundle.main.resourcePath else { return nil }
        return resourcePath + "/python/lib/python-packages"
    }
}
```

**Nota importante:** No modificar el método `run()` en esta fase. La lógica de auto-detección (usar bundle paths en lugar de `@AppStorage`) se implementa en la Fase 9. En esta fase solo se exponen los métodos estáticos para que la Fase 9 pueda conectarlos.
