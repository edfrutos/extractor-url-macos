<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `scripts/release-macos.sh` → Keychain (perfil de notarización, clave EdDSA) | El script solo referencia nombres de perfil — nunca lee ni escribe el material secreto directamente |
| `scripts/release-macos.sh` → GitHub (vía `gh`) | Publica un release público y (con confirmación manual del usuario) actualiza `appcast.xml` en `main` — acción visible, no automatizada sin revisión humana del resumen final |
| Binario `.app` firmado y notarizado → usuarios finales vía Sparkle | El ticket de notarización grapado (`stapler staple`) es lo que permite que Gatekeeper confíe en el binario sin verificación de red en el primer arranque |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-01 | Information Disclosure | Credenciales de notarización / clave EdDSA | mitigate | Nunca en el script ni en el repo — solo nombres de perfil de Keychain, generados y almacenados manualmente por el usuario fuera de cualquier archivo versionado. Verificado por acceptance criteria de Task 1 (grep de secretos). |
| T-13-02 | Tampering | Binario descargado por `_ensure_sparkle_tools` (tarball de Sparkle CLI tools) | mitigate | Descargado directamente de `sparkle-project/Sparkle` releases oficiales vía `gh api`/`gh release download` — mismo repo ya auditado en la Fase 12, sin mirrors ni CDNs de terceros. |
| T-13-03 | Repudiation | `gh release create` público sin confirmación | mitigate | El script imprime el resumen y las instrucciones de `git push` del appcast en vez de ejecutarlas automáticamente — el release en sí (`gh release create`) SÍ se ejecuta como parte del pipeline (es la acción central del script, con `--wait` de notarytool y validaciones previas que garantizan que solo se publica un build ya notarizado y válido), pero el commit del appcast a `main` (el paso que activa el feed para usuarios existentes) queda bajo control explícito del usuario. |
| T-13-SC | Tampering | npm/pip/cargo installs | accept | Esta fase no añade dependencias de paquetes — descarga un tarball de release de GitHub (ver T-13-02), no un paquete de un registro npm/pip/cargo. |
</threat_model>
