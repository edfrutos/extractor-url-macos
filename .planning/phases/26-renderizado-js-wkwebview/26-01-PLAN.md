# 26-01 — CLI: `--js-external` y `--file` + `--base-url`

## Objetivo

Que la CLI pueda (1) avisar de que una página necesita JavaScript sin
renderizarla ella y (2) convertir un HTML ya renderizado resolviendo enlaces
contra su URL de origen. Sin los flags nuevos, el comportamiento es
idéntico al actual (los tests existentes no cambian).

## Tareas

### T1 — `ExternalRenderSession` en `core.py` (WKJS-03)

- Clase nueva junto a `PlaywrightSession`:
  - Context manager (`__enter__`/`__exit__` sin efecto).
  - Atributo `render_needed: bool = False`.
  - Docstring: la usa quien llama a la CLI y renderiza por su cuenta (la app
    App Store, con `WKWebView`).
- Tipos: los parámetros `session` pasan a
  `Optional[Union["PlaywrightSession", "ExternalRenderSession"]]`, o a un
  alias `RenderSession`, en `_fetch_raw`, `_download`,
  `_fetch_via_playwright`, `_fetch_soup`, `extract_formatted_content` y
  `extract_html_structure_to_markdown`.
- `_fetch_via_playwright()`: si `isinstance(session, ExternalRenderSession)`,
  pone `session.render_needed = True` y devuelve `None` **antes** de
  importar `playwright`.
- `_download()`, rama 401/403: con `ExternalRenderSession` se propaga el
  error igual que con `js_mode == "off"` (sin pedir render; ver
  `26-RESEARCH.md`).
- `_fetch_raw()`: si la sesión es externa y quedó `render_needed`, no se
  escribe la caché.

### T2 — CLI en `extractor_url.py` (WKJS-01, WKJS-03)

- `--js-external`. Ayuda: «No usa Playwright: si la página necesita
  JavaScript, lo indica en el JSON (js_render_needed) para que lo renderice
  quien llama».
  - Compatible con `--js`/`--no-js`.
  - Con `--batch` → error, código 2 (la app no lo usa; así no hay que
    definir el contrato por línea).
- `--base-url URL`:
  - Solo con `--file`; sin él → `Error: --base-url requiere --file.`,
    código 2.
  - Esquema distinto de http/https → error claro, código 2.
- En `main()`:
  - Sesión: `ExternalRenderSession()` si `args.js_external`; si no,
    `PlaywrightSession()`.
  - Con `--base-url`, la base de enlaces e imágenes es esa URL. Añadir a
    `_read_local_html` / `_fetch_raw` / `extract_formatted_content` un
    parámetro opcional `base_url`, con prioridad sobre canonical/og:url.
  - `url` del JSON y del historial = `--base-url`, no el `file://`
    temporal.
  - Con `--js-external`:
    - El payload JSON (éxito y error) añade
      `"js_render_needed": session.render_needed`.
    - Sin el flag no se añade la clave (contrato intacto).
  - Si `render_needed`: sin `_lookup_title()` (`title: null`) y sin entrada
    de historial (pasada provisional; la escribe la segunda pasada).
- Sin `--json`, `--js-external` solo afecta a que no se use Playwright. El
  aviso va a stderr: «La página parece necesitar JavaScript; renderízala y
  vuelve a pasarla con --file y --base-url.»

### T3 — Tests `tests/test_external_render.py`

Sin red; se mockea `core._HTTP_SESSION.get` como en `test_js_fallback.py`.

1. **SPA vacía** (`spa_vacia.html`) con `--js-external --json`:
   - `js_render_needed` es `true`, `status` es `success` y `title` es
     `null`.
   - No se importa `playwright`: `sys.modules` sin él o un mock que falle
     si se llama.
   - No se escribe caché ni historial.
2. **Página rica** con `--js-external --json`: `js_render_needed` es
   `false`, con título e historial normales.
3. **`--js-external --no-js`** con SPA vacía: `false`.
4. **`--js-external --js`** con página rica: `true`.
5. **401/403** con `--js-external --json`: error y `js_render_needed` es
   `false`.
6. **Sin `--js-external`**: el JSON no tiene la clave `js_render_needed`
   (regresión).
7. **`--file` + `--base-url`**: un fixture con enlaces e imágenes
   relativos.
   - En Markdown salen absolutos contra la base.
   - La `url` del JSON y del historial es la base.
   - Gana a un `<link rel="canonical">` distinto.
8. **Errores de argumentos:** `--base-url` sin `--file`, `--base-url ftp://x`
   y `--js-external --batch` → código 2 y mensaje en stderr.
