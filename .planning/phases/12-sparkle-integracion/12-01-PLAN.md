final class CheckForUpdatesViewModel: ObservableObject {
    @Published var canCheckForUpdates = false
    init(updater: SPUUpdater) {
        updater.publisher(for: \.canCheckForUpdates)
            .assign(to: &$canCheckForUpdates)

    @ObservedObject private var checkForUpdatesViewModel: CheckForUpdatesViewModel
    private let updater: SPUUpdater

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `SUFeedURL` (Info.plist) → red pública | La app hace una petición HTTPS de solo lectura a `raw.githubusercontent.com` para leer el appcast — sin credenciales, sin datos de usuario enviados |
| Appcast → instalación de código ejecutable | Sparkle instala y ejecuta binarios descargados del `<enclosure>` del appcast — la única barrera de confianza es la firma EdDSA (`SUPublicEDKey`), que en esta fase queda con un placeholder inerte (no valida nada real todavía) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Spoofing | `SUPublicEDKey` placeholder | accept (temporal) | Mientras el placeholder `PENDIENTE-FASE-13` esté en el binario, Sparkle no podrá verificar firmas reales — pero tampoco hay appcast real publicado todavía (Fase 13 los introduce juntos). No supone riesgo porque no hay update real que instalar hasta entonces. |
| T-12-02 | Tampering | Descarga del paquete SPM Sparkle | accept | Paquete oficial `sparkle-project/Sparkle`, resuelto por Xcode con verificación de checksums estándar de SPM — sin mecanismo custom de descarga que auditar en esta fase. |
| T-12-SC | Tampering | npm/pip/cargo installs | accept | Esta fase añade una dependencia SPM (Sparkle, paquete oficial de referencia — ver Package Legitimacy Audit del research), no npm/pip/cargo. Sin script de instalación custom. |
</threat_model>
